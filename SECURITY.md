# Security Policy

## Supported Versions

We ship security fixes in the latest release. Please reproduce on the current released version before reporting. We do not backport fixes to older releases.

## Reporting a Vulnerability

Report privately. **Do not open a public issue or PR for a suspected vulnerability.**

- **Preferred:** GitHub private vulnerability reporting via the **"Report a vulnerability"** button under this repo's **Security** tab. This routes to the maintainers, keeps the report private until a fix is ready, and lets us issue a CVE through GitHub if warranted.
- **Email:** security@usespotlight.ai

We acknowledge valid reports and will keep you updated on remediation. Please give us a reasonable window to fix before any public disclosure.

## Recognition

We do not offer a monetary bounty. For a valid, in-scope report we credit you on the published GitHub Security Advisory and name you as the reporter in the associated CVE. Let us know how you'd like to be credited (name or handle).
